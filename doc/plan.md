**この文書は、この拡張で作業する開発者と AI への引き継ぎ。** 決定・その前提・
確かめた事実・見送った案・経緯を置く。利用者向けの説明は `README.md`。

## 境界

  依頼文にして利用者に渡す（下の「他のリポジトリへの依頼」）

  「再生追従とシーク」。プレイヤーとの間にプロトコルは無い

### 外から見える値のうち、こちらで決めたもの（公開前なら変えるのは安い）

利用者が決めたのは名前・publisher・言語 ID まで。以下はこちらで置いた。
**変える費用：`package.json`・`src/extension.ts`・`README.md` の3か所で、
公開前なら利用者側に波及しない。**

- コマンド ID：`y8960mml.compile` / `y8960mml.play` / `y8960mml.playParts` /
  `y8960mml.stop` / `y8960mml.duplicateTrack` / `y8960mml.renameTrack` /
  `y8960mml.deleteTrack` / `y8960mml.tie` / `y8960mml.portamento` /
  `y8960mml.untie` / `y8960mml.unportamento`（トラックの3つと繋ぎの4つは利用者が
  提案のまま了承。**公開後なので、変えると利用者のキーバインドが切れる**）
- 設定キー：`y8960mml.compilerPath` / `playerPath` / `compileOnSave` / `outDir` /
  `playerTick` / `playerRepeat` / `playerMute` / `detectFromContent`
  （`playerRepeat`・`playerMute`・`playParts` は利用者が提案のまま了承）
- キーバインドは置いていない（F5 はデバッグと取り合う。止めるコマンドにも、いまは
  要らないと利用者が決めた）

トラックの3つのコマンドの決めごと（どれも利用者の決定）。

- **複製は `#assign` を写さない。** 1つのチャンネルを持てるトラックは1つだけで、
  割り当てを写すと必ずコンパイルが通らない。複製の後に「複製先の `#assign` を
  書いてください」と出す。前提：`#assign` の重複がエラーであること
- **削除は `#assign` とトラック行の両方を消す。** `#assign` だけ残す案は採らない
- **複製先・改名先に選べるのは空いているトラックだけ**（`#assign` もトラック行も
  無いもの）。上書きも入れ替えも起きない。16本すべて埋まっていればその旨を出す
- 複製したトラック行は、**元の行のすぐ下**に1行ずつ入れる（末尾にまとめない）。
  節ごとに各トラックを並べて書く書き方をそのまま保つため
- 行の中身は**生のまま**写す。`\` の連結も行末の形もそのままで、トラック名の1文字
  だけを置き換える
- 削除は確認のダイアログを出す（消す行の数を添える）。改名と複製は出さない
- どれも文書を保存しない。**選択中に文書が変わったら何もしない** ―― オフセットを
  選ばせる前に取っているため、変わった文書に当てると壊れる

「パートを選んで再生」は、選んだトラックごとに `--mute !X` を渡す（`!` の指定が
複数あると、そのどれかに当たるものだけが鳴る）。全部を選んだときは何も渡さない。
このコマンドでは `playerMute` を使わない ―― 設定の `!` の指定が選んだものをさらに
狭めてしまうため。選んだトラックは文書ごとに覚え、拡張が動いている間だけ次の選択の
初期値にする。

## CLI について確かめた事実

2026-09-19、`y8mmlc`（コンパイラのリポジトリの `build/` にあった実行ファイル。
そのときの HEAD は e066267）と
`y8960player` を手で走らせて確かめた（**確認済み**）。

- 終了コード 0 成功 / 1 コンパイル失敗 / 2 引数の誤り（引数なしで 2、`--help` で 0）
- 診断は stderr。形は `<パス>[:<行>[:<桁>]]: error|warning: <文面>`。依頼書にあった
  3形式のほかに、**行を指さない error**（`nosuch.mml: error: cannot open the file`）
  がある。`<パス>:<行>: error:`（桁なし）は手で走らせた範囲では出なかった
- 桁は UTF-8 のバイト数（`#voice 128 "あ", zz` の `zz` が 19）
- `\` の行連結をまたいでも、行と桁は物理行で指す（連結後の3行目の `@999` を `3:6`）
- `#pcmbank` の JSON の誤りも、MML の `#pcmbank` の行を指す
- 成功時の stdout は `<パス> (<N> bytes)`。パスは渡したとおりの形（相対なら相対）
- **パスと出力の文字コード（9c25143 以降）**：同日に 9c25143 のビルドで確かめた。
  stdout・stderr は UTF-8（`誤り.mml` の診断のパスが UTF-8 のバイト列）。`ü😀` を
  含む絶対パスを渡しても通る。`#pcmbank 音.json` が開ける（JSON の中身の誤りまで進む）。
  茎が `曲` のソースの出力名は `_.SQ` になり、警告が出る。e066267 のビルドでは、
  パスが CP932 で出て、CP932 外の文字を含む絶対パスと日本語の `#pcmbank` が開けなかった
- **`--out-dir` のフォルダが無いと** `y8mmlc: cannot write '...'` を出して終了コード 1。
  この行は診断の形に当たらない
- `y8960player` は `--help` を知らず、使い方を出して終了コード 1。起動後 2 秒は
  動き続け、プロセスの kill で止まった（音が出たかは確かめていない）

2026-09-21、同じ `y8mmlc` で**行の種類の決まり方**を確かめた（**確認済み**。端の
場合を並べたソースを食わせ、診断を見た）。`src/track.ts` はこの解釈に合わせてある。

- コメント行を `\` で終えると**次の行も読み飛ばされる**（続けて書いた `#assign` が
  効かず、診断も出ない）
- `#assign` は `#` の後がちょうど4語。`#assign E SCC 3 extra` は
  `#assign takes a track name, a device and a channel`
- トラック名は大文字1文字（`#assign f SCC 4` は `'f' is not a track name (A-P)`）。
  トラック行はトラック名の次が空白（`Ecde` は `a track name is followed by a space`）。
  行頭に空白は置けない（` E cde` は
  `a line begins with a track name (A-P), '#' or ';'`）
- 複製・改名・削除を当てた結果をコンパイルした：**改名と削除は終了コード 0**、
  **複製は `track C has MML but no #assign` で 1**、`#assign` を1行書き足すと 0。
  複製が通らないのは決めたとおりの挙動

同日、**繋ぐ・外す**も実物で確かめた（**確認済み**）。コンパイラの
`examples/demo.mml` に、全体を選んだときの編集を当てて `y8mmlc` を走らせた。

- タイ・レガートで繋いだもの、ポルタメントで繋いだもの、どちらも終了コード 0
- 繋いでから外すと、元のテキストとバイト単位で一致した
- リズムのトラック（`D`、チャンネル 10）には何も書かず、名前を返した
- ブロックの `[1` と `[2` の音符の間は繋がなかった（**この確認で見つけて直した**。
  直す前は1番カッコの音符と2番カッコの音符を繋いでいた）

## リリースの手順

GitHub のリリースに VSIX を載せる。Marketplace には出していない。手元で作り、`gh` で
出す（利用者の決定。GitHub Actions で作る案は見送った）。

1. `package.json` の `version` を上げる。VSIX に入れる文法を変えるなら
   `config.compilerTag` をコンパイラのタグにする。`scripts/copy-grammar.mjs` は
   隣の Y8960MMLCompiler からそのタグの版の文法を `git show` で取る（作業ツリーの
   中身は使わない）
2. `npm test` と `npm run e2e`（`Y8MMLC`・`Y8960PLAYER` はコンパイラとプレイヤーの
   リリース版を指す。`Y8960MML_E2E_PLAY=1`）
3. `npx vsce package` → `y8960mml-helper-<版>.vsix`
4. コミットして push し、`gh release create v<版> <vsix> --target master`。タグの形は
   コンパイラ・シーケンサと同じ `v<版>`

版はコンパイラ・シーケンサの最初のリリースに揃えて 0.1.0 から始めた（利用者の決定）。

## 予定：トラック行の音価の表示（字句解析まで done）

**表示はまだ無い。** ただし土台の字句解析は `src/mml.ts` にできている（繋ぐ・外す
コマンドが同じものを使う）。**残るのは長さの計算と表示だけ。**

### 決定と前提

| 決定 | 前提（これが変われば見直す） |
|---|---|
| 音価の合計は**拡張の中で MML を解釈して**出す。コンパイラには頼まない（2026-09-21 利用者の決定） | 編集中の目安として欲しい。`y8mmlc` は曲全体が通らないと何も出さないので、書きかけのファイルでは出せない。走らせる分だけ遅くもなる |
| 出すのは「**その行に書かれた音価の合計**」。繰り返しやダカーポを展開した「実際に鳴る長さ」ではない | 用途が「小節が埋まっているかの目安」。`\|: :\|4` の中の行は、書かれた合計と鳴る長さが違う |
| 単位は四分音符換算の拍（tick を 48 で割る） | 四分音符 48 tick、全音符 192 tick |

### 数えるもの（`src/core/mml.cpp`・`doc/mml-reference.md` を読んだ。走らせてはいない）

- **時間を取るのは音符・`R`・`N`・`@W` の4つだけ。** 残りのコマンドは読み飛ばす
- 長さは、数を書けば `192 / n` の切り捨て、省けば連符の割り当て、それも無ければ
  `L` の値。長さ 0 は 0 tick
- 付点は「足した分の半分」を足していく（`C4..` は 48 ＋ 24 ＋ 12）。**長さを省いた
  音符にも `L` にも付く**
- **`L` の値は行をまたいで続く。** 行だけを見ても合計は決まらないので、トラックの
  先頭から順に数えて行で区切る
- 連符 `{ }`*n* は、囲みの中の音名・`R`・`N` だけを数えて割る（切り捨て）。`&` と
  `@W` は数えない。入れ子は無いが、**行はまたげる**
- `X名前;` は展開して数える（8段まで）、`=名前;` は数として解く
- **書き方は3つ** ―― ふつう／ADPCM（長さの扱いはふつうと同じ）／リズム（`L` が
  無く既定は四分音符、楽器の並びの後ろに長さを書く）。どれかは `#assign` の
  チャンネルで決まる（9 が ADPCM、10 がリズム。`src/core/device.cpp` を読んだ）

### 構造

- **できているもの**：`src/mml.ts` の字句解析（3つの書き方、`$` の2桁、`=名前;`、
  空白と改行をまたぐ命令、壊れたテキストで止まらないこと）。`src/track.ts` の
  `trackViews` が、トラックの MML を1本のテキストとして渡し、そこの位置を文書の
  位置に戻す
- **残っているもの**：`getLen` と `dots` に当たる長さの計算（`{ }` の連符と `L` の
  持ち越しを含む）、`X名前;` の展開、そして表示
- **`X名前;` は今は中を見ていない。** 音価では展開して数える必要がある（8段まで）
- 書きかけのテキストで落ちない・止まらないこと。読めないところに当たったら、
  その行の値を**出さない**。誤った数を出すより無いほうがよい

### ずれに気づく仕組み

二重持ちの危険は、コンパイラが変わったときに**黙ってずれる**こと。気をつけるのでは
なく、試験で落ちるようにする。

- 繰り返しの無い曲を並べ、`y8mmlc` を走らせて、拡張のトラック合計と `.SQ` の
  音符・休符・`@W` の合計を突き合わせる。`Y8MMLC` が無ければ飛ばす
  （`compile.test.ts` と同じ形）
- `.SQ` は `Y8SQ` ＋版＋全体の長さの後ろに `{種類, 長さ16bit, 中身}` の塊が並ぶ。
  トラックの塊は「トラック番号・デバイス・チャンネル・イベント列」。イベントの
  長さは 128 未満なら1バイト、それ以上なら上位バイトに `$80` を立てた2バイト
  （`writer.cpp`・`mml.cpp` を読んだ。走らせてはいない）
- これは**試験の中だけ**の話で、動くときに `.SQ` を読むわけではない。「頼るのは
  コマンドラインだけ」という境界は動かさない
- ただし `.SQ` の形式の文書はコンパイラのリポジトリに無い（`bytecode.md` が
  参照されているが `doc/` に無い）。着手時に、文書化の依頼を出すか、試験が読むのを
  音符・休符・`@W` だけに留めるかを決める

### 着手前に決めること

外に出る値が混ざっている。**決める直前に利用者に振る。**

- 表示手段：インレイヒント（行末に常時）／ステータスバー（カーソルのある行）／両方
- 端数の見せ方：`1.5 拍` か `3/2 拍` か tick のまま
- トラックごとの合計も出すか
- 小節の判定まで行くか。**MML に拍子のメタコマンドは無い**ので、拍子を設定で
  与えるか、判定を作らないかを選ぶことになる
- コマンド ID・設定キー（公開後なので、変えると利用者のキーバインドや設定が切れる）

### 値段の目安（**未検証**の見積もり）

| | 目安 |
|---|---|
| 長さの計算そのもの（`getLen`・`dots` に当たるもの） | 数十行 |

## 見送った案

- **`--diag=json` をコンパイラに頼む**：テキストの並びで足りる。利用者の了承済み
- **パスの文字コードを `wmain` とワイド文字のパスで直す**（コンパイラ側）：変える量が
  多い。利用者がマニフェスト案を選んだ
- **コンパイラ・プレイヤー・エミュレータの DLL を VSIX に同梱する**：利用者が同梱
  しないと決めた。調べた事実（2026-09-19、**確認済み**：各リポジトリの LICENSE と
  CMakeLists、実行ファイル内の文字列を見た）：
  - ライセンスは障害にならない。本体はどれも MIT。同梱される第三者のコードは
    ymfm（BSD-3）、emu2149/2212/2413/76489/8950（MIT）、MAME 由来の
    ay8910/mpeg_audio/ymz280b（BSD-3）、SDL3（zlib、プレイヤーに静的リンク）。
    同梱するなら MIT・BSD の表示を VSIX に入れる必要がある
  - 6本とも VCRUNTIME140/MSVCP140 を参照する。同梱するなら、各リポジトリで `/MT` に
    するか、ランタイムの DLL も同梱する必要がある
  - Windows 専用なので `vsce package --target win32-x64` になる。一式で約 3.2MB
  - 同梱に切り替えるなら、`compilerPath`・`playerPath` の既定を「空＝同梱」にし、
    設定があればそちらを優先する形が考えられる
- **音価の合計をコンパイラに出させる**（`y8mmlc` に選択肢を足してもらう）：見送った。
  理由：編集中の目安として欲しい情報なのに、コンパイラは曲全体が通らないと何も
  出さない。書きかけのファイルでは出せず、走らせる分だけ遅い（2026-09-21
  利用者の決定）。二重持ちを避けられる唯一の案だったので、ずれを試験で捕まえる
  ことにした（上の「予定」）
- **`.SQ` を読んで音価を出す**：見送った。理由：行との対応が無く、行ごとの目安に
  ならない。動くときに形式へ頼ると境界が変わる。**試験の突き合わせにだけ使う案は
  残っている**
- **診断のパスを見てファイルを選ぶ**：対象は常に1本なので読まない
- **`-o` を渡して出力名を拡張が決める**：出力名の規則（大文字・8文字・非 ASCII の
  置き換え）を拡張の側で再現することになり、コンパイラと二重に持つ
