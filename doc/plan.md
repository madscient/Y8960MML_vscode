## 境界

- 再生位置の追従とシークは作らない。理由はコンパイラ側の `doc/plan.md`
  「再生追従とシーク」。プレイヤーとの間にプロトコルは無い

## CLI について確かめた事実

2026-09-19、`y8mmlc`（コンパイラのリポジトリの `build/` にあった実行ファイル。
そのときの HEAD は e066267）と
`y8960player` を手で走らせて確かめた（**確認済み**）。

- 終了コード 0 成功 / 1 コンパイル失敗 / 2 引数の誤り（引数なしで 2、`--help` で 0）
- 診断は stderr。形は `<パス>[:<行>[:<桁>]]: error|warning: <文面>`。依頼書にあった
  3形式のほかに、**行を指さない error**（`nosuch.mml: error: cannot open the file`）
  がある。`<パス>:<行>: error:`（桁なし）は手で走らせた範囲では出なかった
- 桁は UTF-8 のバイト数（`#voice 128 "あ", zz` の `zz` が 19）
- `\` の行連結をまたいでも、行と桁は物理行で指す（連結後の3行目の `@999` を `3:6`）
- `#pcmbank` の JSON の誤りも、MML の `#pcmbank` の行を指す
- 成功時の stdout は `<パス> (<N> bytes)`。パスは渡したとおりの形（相対なら相対）
- **パスと出力の文字コード（9c25143 以降）**：同日に 9c25143 のビルドで確かめた。
  stdout・stderr は UTF-8（`誤り.mml` の診断のパスが UTF-8 のバイト列）。`ü😀` を
  含む絶対パスを渡しても通る。`#pcmbank 音.json` が開ける（JSON の中身の誤りまで進む）。
  茎が `曲` のソースの出力名は `_.SQ` になり、警告が出る。e066267 のビルドでは、
  パスが CP932 で出て、CP932 外の文字を含む絶対パスと日本語の `#pcmbank` が開けなかった
- **`--out-dir` のフォルダが無いと** `y8mmlc: cannot write '...'` を出して終了コード 1。
  この行は診断の形に当たらない
- `y8960player` は `--help` を知らず、使い方を出して終了コード 1。起動後 2 秒は
  動き続け、プロセスの kill で止まった（音が出たかは確かめていない）

## 試験

`npm test`。`src/test/` の3本。

- `cli.test.ts`：診断・出力行の解析、桁の換算、中身による判定
- `compile.test.ts`：実物の `y8mmlc` を走らせる。環境変数 `Y8MMLC` に実行ファイルを
  入れる。無ければ飛ばす
- `grammar.test.ts`：写した文法を `vscode-textmate` と `vscode-oniguruma`（VS Code が
  使うのと同じライブラリ）でトークン化する。隣に Y8960MMLCompiler があれば
  `examples/demo.mml` も通す

`npm run e2e`：VS Code を別のユーザーデータで起動し、拡張ホストの中で
`src/e2e/suite.ts` を走らせる。環境変数は `scripts/run-e2e.mjs` の先頭に書いてある
（`Y8MMLC` 必須、`VSCODE_EXE` が無ければ VS Code を落としてくる、
`Y8960MML_E2E_PLAY=1` と `Y8960PLAYER` で再生も試す）。

2026-09-19 に VS Code 1.135.0 で4件とも通った（**確認済み**）：言語 ID が
`y8960mml` になる／コマンドでコンパイルして診断が `0:16-18` に出る（桁の換算込み）／
直してコマンドを打つと保存してから通り、診断が消える／`compileOnSave` で保存時に
走る／再生で `y8960player` が起動し、停止コマンドで終わる。

色付けの見た目は、2026-09-19 に利用者が F5 で起動した VS Code で見て、問題ないとした
（**確認済み**。利用者の目視）。同日、利用者が「コンパイルして再生」で音が鳴ることを
確かめた（**確認済み**。利用者の耳。`.PC` を伴わない曲）。

## 見送った案

- **`--diag=json` をコンパイラに頼む**：テキストの並びで足りる。利用者の了承済み
- **パスの文字コードを `wmain` とワイド文字のパスで直す**（コンパイラ側）：変える量が
  多い。利用者がマニフェスト案を選んだ
- **コンパイラ・プレイヤー・エミュレータの DLL を VSIX に同梱する**：利用者が同梱
  しないと決めた。調べた事実（2026-09-19、**確認済み**：各リポジトリの LICENSE と
  CMakeLists、実行ファイル内の文字列を見た）：
  - ライセンスは障害にならない。本体はどれも MIT。同梱される第三者のコードは
    ymfm（BSD-3）、emu2149/2212/2413/76489/8950（MIT）、MAME 由来の
    ay8910/mpeg_audio/ymz280b（BSD-3）、SDL3（zlib、プレイヤーに静的リンク）。
    同梱するなら MIT・BSD の表示を VSIX に入れる必要がある
  - 6本とも VCRUNTIME140/MSVCP140 を参照する。同梱するなら、各リポジトリで `/MT` に
    するか、ランタイムの DLL も同梱する必要がある
  - Windows 専用なので `vsce package --target win32-x64` になる。一式で約 3.2MB
  - 同梱に切り替えるなら、`compilerPath`・`playerPath` の既定を「空＝同梱」にし、
    設定があればそちらを優先する形が考えられる
- **診断のパスを見てファイルを選ぶ**：対象は常に1本なので読まない
- **`-o` を渡して出力名を拡張が決める**：出力名の規則（大文字・8文字・非 ASCII の
  置き換え）を拡張の側で再現することになり、コンパイラと二重に持つ
